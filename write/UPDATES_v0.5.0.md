# v0.5.0：对话记忆与学生学习情境

[首页](../README.zh-CN.md) · [English](UPDATES_v0.5.0.en.md) · [安装说明](../GETTING_STARTED.md) · [发布验证](../evidence/RELEASE_VALIDATION.md)

知识空间与 Note AI 现在恢复更长的对话历史，保存较早轮次的滚动摘要，并检索当前学生在当前课程中的相关记录。学生继续选择已配置的模型，判断和使用 AI 建议。这是应用层的持久化与检索，未进行模型权重训练或微调，也未证明学习效果。

## 对话如何延续

两个入口共用分页历史读取，不再只查询 Note 最近 12 条或知识空间最近 40 条消息。模型输入保留历史预算内的近期完整轮次；较早消息逐步写入当前线程的 `conversation_memory` JSONB 字段，原始对话仍保留。

摘要指令要求保留目标、要求、修正、决定与待解决问题，并区分学生陈述和 AI 建议。每轮最多处理 100 条较早记录，摘要输入目标为 16,000 字符，摘要上限为 4,500 字符，小窗口模型会进一步缩小。超长历史消息保留片段并标明省略。摘要逐轮推进，一次回复未必覆盖全部积压历史。

历史或持久化记忆读取失败时，中止受影响的请求；摘要生成或保存失败时保留旧检查点，在后续轮次重试。摘要生成会调用已配置的外部模型，可能增加 API 费用。摘要可能遗漏或误述信息，不能代替完整对话或学生确认。

## 上下文按所选模型配置

[modelContextBudget.ts](../api/src/services/modelContextBudget.ts) 保留模型选择，按代码中的窗口映射分配历史预算。映射包含部分 1M 模型、1,048,576 token 的 Gemini 2.5，以及 262,144 token 的 Kimi K2.5/2.6/2.7；未知模型保守按 32,768 token 处理。这些是应用配置假设，不能保证模型提供方或中转账户开放相同上限。

历史使用 UTF-8 字节与消息开销估算，预留约 25% 的名义窗口及额外 8,000 单位给其他输入和输出。它不是提供方的精确分词器，也不能精确约束完整的图片、工具与文本请求。知识空间的回退候选模型分别适配预算。单条超大的最后消息即使超过历史估算预算也会被保留。本次发布没有完成整窗 1M 请求压力测试或全部提供方组合验证。

## 如何根据学生记录提供指导

课程权限检查后，[studentLearningContext.ts](../api/src/services/studentLearningContext.ts) 从学生当前可进入的本课程空间重新读取：

- 最近最多 40 篇本人未删除的 Note，按问题相关词排序，选最多 5 篇。
- 知识空间与本人创建的 AI Note 对话各最多 20 条近期学生提问，合并排序选最多 8 条。
- 本人近期对话的最多 3 份派生摘要，附来源标识与时间。

这是有限范围的关键词选择和近期记忆检索，未穷尽全部历史，也不建立永久能力标签。查询排除其他学生、其他课程、已删除的 Note/线程及当前不可进入的空间。派生摘要可能含 AI 建议，不能默认视为学生接受的决定。来源内容按引用数据处理，当前修正与当前 Note 优先；这些提示词不会向教师提供学生画像。

选中的学习情境、对话历史和摘要所需较早消息会发送给课程配置的 AI 提供方，运营者应向用户说明这一数据流。本版未增加独立的记忆查看、编辑或删除界面；摘要刷新本身也不保证立即清除先前概括的信息。

## 已有系统如何升级

1. 备份数据库，结合已有表结构检查 [086_conversation_memory.sql](../supabase/migrations/086_conversation_memory.sql)。它用 `ADD COLUMN IF NOT EXISTS` 为 `agent_conversations` 和 `note_conversation_threads` 增加 `conversation_memory jsonb NOT NULL DEFAULT '{}'::jsonb`。
2. 先执行检查后的迁移，再按原有流程构建并部署 API。这次修改不需要新增前端环境变量或依赖包。
3. 在隔离项目验证学生与课程边界、长对话、小窗口模型、提供方失败及检查点持久化；另行确认账户实际请求上限。

现有路由授权仍必不可少；迁移不新增 RLS 策略或权限授予。历史迁移目录仍不是已验证的全新安装序列。更旧安装请一并查看 [v0.4.0 升级说明](UPDATES_v0.4.0.md)。公开仓库发布不会自动部署应用或修改数据库。
